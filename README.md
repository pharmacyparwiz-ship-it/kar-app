# کار — بازار کار محلی افغانستان

پلتفرم فول‌استک بازار کار محلی: کارجو و کارفرما را مستقیم به هم وصل می‌کند،
بدون واسطه و بدون کمیشن. این نسخه برای انتشار عمومی (production) آماده شده:
دیتابیس PostgreSQL واقعی، محافظت در برابر حملات brute-force، محدودیت نرخ
درخواست (rate limiting)، و بررسی امنیتی فایل‌های آپلودی.

## پشته فنی

- **Next.js 14** (App Router) — هم فرانت‌اند و هم بک‌اند (API Routes) در یک پروژه
- **Prisma ORM** + **PostgreSQL** — دیتابیس واقعی و پایدار (نه فایل محلی)
- **JWT** برای احراز هویت، ذخیره در کوکی `httpOnly`، با الزام رمز قوی
- **bcryptjs** برای هش کردن رمز عبور
- **zod** برای اعتبارسنجی ورودی‌ها

## قابلیت‌های امنیتی این نسخه

- ✅ دیتابیس PostgreSQL واقعی (پایدار، قابل backup، مقیاس‌پذیر)
- ✅ الزام `JWT_SECRET` قوی — برنامه با مقدار پیش‌فرض یا کوتاه اجرا نمی‌شود
- ✅ قفل خودکار حساب بعد از ۵ تلاش ناموفق ورود (۱۵ دقیقه)
- ✅ محدودیت نرخ درخواست (Rate Limiting) روی ورود، ثبت‌نام، ثبت آگهی، ثبت پروفایل، و آپلود عکس
- ✅ بررسی محتوای واقعی فایل آپلودی (magic bytes) — نه فقط پسوند یا MIME ادعاشده
- ✅ هدرهای امنیتی HTTP (X-Frame-Options، X-Content-Type-Options و غیره)
- ✅ رمزهای عبور با bcrypt هش می‌شوند؛ هیچ‌وقت متن ساده ذخیره نمی‌شوند

### چیزی که هنوز اضافه نشده (و چرا)

- **تأیید شماره موبایل با OTP (پیامک):** نیاز به یک سرویس پیامک پولی (مثل
  Twilio) دارد که باید خودتان حساب بسازید. کد این بخش آماده افزودن است — اگر
  خواستید، در یک مرحله جدا اضافه می‌کنیم.

## اجرای محلی (روی کامپیوتر خودتان)

پیش‌نیاز: [Node.js نسخه ۱۸ یا بالاتر](https://nodejs.org)

### ۱. ساخت دیتابیس رایگان PostgreSQL

قبل از هر چیز به یک دیتابیس Postgres نیاز دارید (حتی برای اجرای محلی).
ساده‌ترین گزینه‌های رایگان:

- **[Neon](https://neon.tech)** — رایگان، راه‌اندازی در کمتر از ۲ دقیقه
- **[Supabase](https://supabase.com)** — رایگان، امکانات اضافه هم دارد

مراحل با Neon:
1. حساب رایگان بسازید و یک پروژه جدید بسازید
2. در داشبورد، روی "Connection string" کلیک کنید و آن را کپی کنید
   (چیزی شبیه `postgresql://user:pass@ep-xxx.neon.tech/dbname?sslmode=require`)

### ۲. تنظیم پروژه

```bash
# فایل zip را از حالت فشرده خارج کنید و وارد پوشه شوید
cd kar-app

# وابستگی‌ها را نصب کنید
npm install

# فایل env نمونه را کپی کنید
copy .env.example .env      # ویندوز (PowerShell)
cp .env.example .env        # مک / لینوکس
```

فایل `.env` را باز کنید و:
- `DATABASE_URL` را با connection string که از Neon/Supabase گرفتید جایگزین کنید
- `JWT_SECRET` را با یک رشته تصادفی طولانی جایگزین کنید. برای ساختنش:
  ```bash
  # مک/لینوکس یا Git Bash
  openssl rand -base64 32

  # ویندوز PowerShell (اگر openssl ندارید)
  node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
  ```
  ⚠️ برنامه اگر این مقدار خالی، کوتاه، یا همان مقدار نمونه باشد، **اجرا نمی‌شود** — این عمداً است تا کسی سایت را با رمز ضعیف منتشر نکند.

### ۳. ساخت جداول و اجرا

```bash
npx prisma generate
npx prisma db push
npm run db:seed    # اختیاری — چند آگهی نمونه برای شروع
npm run dev
```

سپس مرورگر را باز کنید: **http://localhost:3000**

**حساب نمونه کارفرما** (بعد از `db:seed`): شماره `0700000000` / رمز `demo1234`

## آماده‌سازی برای Deploy (انتشار آنلاین)

### گزینه پیشنهادی: Vercel + Neon (کاملاً رایگان برای شروع)

1. دیتابیس Neon را طبق مرحله ۱ بالا بسازید (اگر هنوز نساختید)
2. کد را در یک ریپازیتوری گیت‌هاب push کنید
3. در [vercel.com](https://vercel.com) با گیت‌هاب وارد شوید و پروژه را import کنید
4. در تنظیمات پروژه (Settings → Environment Variables) این دو متغیر را اضافه کنید:
   - `DATABASE_URL` — همان connection string از Neon
   - `JWT_SECRET` — همان رشته تصادفی که ساختید (یا یک رشته جدید برای production)
5. Deploy کنید
6. بعد از اولین deploy موفق، یک بار از کامپیوتر خودتان (با DATABASE_URL همان production) این را اجرا کنید تا جداول ساخته شوند:
   ```bash
   npx prisma db push
   npm run db:seed   # اختیاری
   ```

### گزینه دوم: یک VPS شخصی (DigitalOcean، Hetzner و غیره)

```bash
git clone <repo-url>
cd kar-app
npm install
cp .env.example .env   # و DATABASE_URL و JWT_SECRET را تنظیم کنید
npx prisma generate
npx prisma db push
npm run db:seed
npm run build
npm start
```

برای اجرای دائمی:
```bash
npm install -g pm2
pm2 start npm --name kar -- start
pm2 save
```
و یک reverse proxy (nginx) با HTTPS (Let's Encrypt) جلوی آن قرار دهید.

**نکته:** روی VPS، چون فایل‌سیستم دائمی دارید، آپلود عکس در `public/uploads/`
مشکلی ندارد. روی Vercel این‌طور نیست — بخش بعدی را بخوانید.

## پنل مدیریت (Admin)

این پروژه یک پنل مدیریت ساده دارد که در `/admin` قابل دسترسی است — فقط برای
حساب‌هایی که شماره تلفنشان در متغیر `ADMIN_PHONES` باشد.

### فعال‌سازی

در فایل `.env` (و همچنین در تنظیمات Environment Variables روی Vercel/هاست
شما)، شماره تلفن حسابی که می‌خواهید ادمین باشد را وارد کنید:

```
ADMIN_PHONES="0700000000"
```

برای چند ادمین، با کاما جدا کنید:
```
ADMIN_PHONES="0700000000,0799999999"
```

⚠️ بعد از تغییر این متغیر روی Vercel، باید پروژه را دوباره deploy کنید تا
اعمال شود (از داشبورد Vercel: Deployments → سه‌نقطه کنار آخرین deploy → Redeploy).

### چه کاری می‌توانید انجام دهید

بعد از ورود با همان شماره‌ای که در `ADMIN_PHONES` گذاشتید، یک دکمه «پنل
مدیریت» در داشبورد ظاهر می‌شود. از آنجا می‌توانید:
- **آمار کلی** — تعداد کاربران، آگهی‌ها، پروفایل‌ها را ببینید
- **آگهی‌ها** — هر آگهی نامناسب یا تقلبی را حذف کنید (شماره تماس کارفرما هم نمایش داده می‌شود)
- **کارجویان** — پروفایل‌های نامناسب را ببینید و حذف کنید
- **کاربران** — هر حساب را مسدود (بدون حذف داده) یا کاملاً حذف کنید

مسدود کردن، ورود کاربر را غیرفعال می‌کند بدون اینکه اطلاعاتش پاک شود — برای
مواردی که مطمئن نیستید یا می‌خواهید بعداً بررسی کنید مناسب‌تر است. حذف کامل،
همه‌چیز (آگهی‌ها یا پروفایل آن کاربر) را برای همیشه پاک می‌کند.



عکس‌های پروژه به‌صورت پیش‌فرض در `public/uploads/` ذخیره می‌شوند — این روی
VPS خوب کار می‌کند، اما روی **Vercel** (و اکثر هاست‌های serverless) فایل‌سیستم
موقتی است و عکس‌ها ممکن است بعد از مدتی پاک شوند.

اگر روی Vercel دیپلوی می‌کنید، پیشنهاد می‌شود `app/api/upload/route.js` را
طوری تغییر دهید که عکس را در یک سرویس ذخیره‌سازی ابری رایگان بارگذاری کند:
- **[Cloudflare R2](https://developers.cloudflare.com/r2/)** — ۱۰ گیگابایت رایگان در ماه

## نکات امنیتی که رعایت شده

- رمزهای عبور هرگز به‌صورت متن ساده ذخیره نمی‌شوند (bcrypt، cost factor ۱۰)
- نشست‌ها (JWT) در کوکی `httpOnly` نگه‌داری می‌شوند — جاوااسکریپت صفحه نمی‌تواند آن‌ها را بخواند
- بعد از ۵ بار رمز اشتباه، حساب به‌مدت ۱۵ دقیقه قفل می‌شود
- تمام مسیرهای حساس (ورود، ثبت‌نام، ثبت آگهی، آپلود) محدودیت نرخ درخواست دارند
- فایل‌های آپلودی بر اساس محتوای واقعی (نه فقط پسوند) بررسی می‌شوند
- ورودی‌های کاربر با zod اعتبارسنجی می‌شوند؛ Prisma به‌صورت خودکار جلوی SQL injection را می‌گیرد

### محدودیت شناخته‌شده Rate Limiting

سیستم محدودیت نرخ فعلی در حافظه برنامه ذخیره می‌شود (نه یک سرویس جدا مثل
Redis). این برای یک سرور یا یک instance مشکلی ندارد، اما اگر روی چند سرور
همزمان اجرا شوید (که برای این پروژه در مقیاس فعلی بعید است)، محدودیت به‌صورت
مستقل روی هر سرور اعمال می‌شود نه به‌صورت کلی. اگر کاربران زیاد شدند و این
مسئله مهم شد، می‌توان به [Upstash Redis](https://upstash.com) (رایگان برای شروع) ارتقا داد.

## قدم‌های بعدی پیشنهادی

- تأیید شماره موبایل با OTP/SMS (وقتی حساب Twilio یا مشابه ساختید)
- سوییچ آپلود عکس به فضای ابری (اگر روی Vercel دیپلوی می‌کنید)
- صفحه‌بندی (pagination) برای لیست آگهی‌ها وقتی تعداد زیاد شد
- صفحه قوانین استفاده و حریم خصوصی
